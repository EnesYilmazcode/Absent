How it works, in seven stages

One Python process on one laptop, plus Ollama beside it. Filled dots run continuously; hollow dots fire once per instrument.

1 · iPhone captures and posts Safari · getUserMedia → canvas → JPEG q0.8, max side 1280 · every ~80ms

Self-clocking chain, never a fixed frame rate. Raw JPEG body POSTed to /ingest over HTTPS.

2 · Laptop decodes and picks a source uvicorn event loop → BGR ndarray under one lock

Phone frames win. If none arrive for 3 seconds it falls back to the built-in webcam, so the demo cannot end on a frozen picture.

3 · FastSAM segments every frame capture thread · CPU torch · imgsz 512 · 7.4 fps measured (~135ms)

Class-agnostic outlines — it segments objects it was never trained on. CPU on purpose so all 4GB of VRAM belongs to Gemma.

4 · Watch loop decides whether to spend a call own thread · ticks 100ms · four gates

Scene must stir (motion > 0.06), then hold still — same mask count in 6 of the last 8 samples, ~0.8s — then settle. If a handheld camera never settles, a 2.5s patience timer fires anyway.

5 · Gemma names it — once POST 127.0.0.1:11434 · ROI crop only, upscaled ≥768px, base64 · 1.4–1.6s measured

One question: name the single object the person is holding up. Then three filters — a shape hint, a ~50-word blocklist, and a fuzzy match against the manifest so one fork does not become two.

6 · A card appears faded cutout JPEG on disk → sidebar in ~400ms

A real photo of the real object, its name, a timestamp. Nobody pressed anything.

7 · Geometry watches, forever every frame · no model · matches area + centroid within ¼ frame diagonal

Unmatched for 2.0s → status flips, card turns red, banner reads N unaccounted for. Put it back and it flips green. Moving a counted tool out of the zone onto the table keeps it accounted for — only actually disappearing raises the alarm.

How things stream

Phone → laptop

Not a video stream. The phone draws its <video> into a canvas, encodes a JPEG at quality 0.8, and POSTs the raw bytes as the request body — not multipart, not base64 — then schedules the next one 80ms later. Self-clocking: it never gets ahead of the link.

Laptop → browser, video

Single JPEGs polled ~90ms apart, not MJPEG. An MJPEG <img> that drops one frame goes black permanently with no way back. Polling always recovers. The /feed MJPEG route still exists but the main page does not use it.

Laptop → browser, data

Two JSON fetches every 400ms — the manifest and the state object. That poll is the last link in the alert chain, so red hits the screen 2.0s + one poll after the instrument vanishes.

Python → Gemma

One persistent requests.Session to 127.0.0.1:11434, never the word localhost — on Windows localhost resolves to IPv6 first, Ollama binds IPv4 only, and every call was burning a fixed 2 seconds waiting for that to fail. 3.83s before, 1.52s after, same model.

Threads

Three daemon threads: capture, watch, and a startup warm-up call so a cold-start crash cannot happen on stage. Capture and watch hand off exactly two values — an int and a float — which is the cheapest possible handoff.

Call settings

think=false (reasoning out loud is the difference between 123 seconds and 1.4), temperature=0 with seed=42 (three runs byte identical), keep_alive=-1 so Ollama never unloads and the first count on stage does not cost 21 seconds.

Judge questions, condensed

Tap to open. Red line is what not to say.

A clinician

easyDoes this replace my two-person verbal count? If your screen says 7 and my nurse says 8, whose number goes in the chart?

It does not replace it. We watch the field and raise a hand when something we saw stops being there. If we disagree with the nurse, the nurse's number goes in the chart. We are a reason to recount, not a record.

Don't say: it automates the count so the nurse doesn't have to do it twice.

hostileSterile processing already knows what's in the tray, item by item. What does zero-shot naming buy me that the count sheet doesn't?

The sheet says what should be in the tray. It does not say what is on the field, and things get opened onto the field off the sheet all case long. Hand me the tray list and our job gets easier, not pointless — matching a known list is a simpler question than naming cold. We just did not want to require the list to exist.

Don't say: most hospitals don't really use count sheets.

hostileA count discrepancy costs me an intraoperative film, a dose of radiation and OR minutes. What's your false positive rate?

That is the right way to score us. Our tracking flickers today when the segmenter drops a mask for a second or two, and I can show you that in our own log. So this is a prompt to recount, not a trigger for an X-ray. At this false alarm rate you would not run it in a room yet.

Don't say: it's just a threshold we haven't tuned.

hostileYour manifest caps at eight. A lap tray is sixty instruments. What happens to instrument sixty-one?

It is never on the manifest, so it can never be flagged — and I want to say that plainly, because that is the dangerous direction. The cap is a demo guardrail so a dark frame cannot invent items. We have not run this at tray scale, and at tray scale the failure would be silence, not a false alarm.

Don't say: that's one constant, we can raise it to sixty.

hostileYour screen says "inside the patient." You don't know that. It could be on the floor.

You are right, and the label is wrong. All the geometry knows is that a shape it was tracking stopped being visible. It should read unaccounted for, which is the word the count actually uses. We will change it.

Don't say: it's just demo copy, everyone knows what we mean.

mediumTwo thirds of retained items are sponges, not instruments. Why should I care about the smaller half?

Sponges already have a product — RF tags and barcode counters ship today. Nobody is putting a tag on every hemostat, so instruments are the part with no answer. And a blood-soaked sponge on a bloody field is the hardest thing in the room to segment. We have not tried it and I am not going to claim it.

Don't say: sponges would work exactly the same way.

A senior ML engineer

easyWhat is Gemma actually responsible for, and what breaks if I delete it?

Gemma names each object once, the moment it enters the count zone, with no training data. That is the entire naming layer. Delete it and you have coloured outlines with no names, and you need a labeled instrument dataset — exactly what we designed the project around removing. It does not run the alarm. That part is geometry.

Don't say: Gemma powers the whole system.

hostileYOLO-World, OWL-ViT and GroundingDINO name things zero-shot too, with boxes, at frame rate. Why a 4.6B VLM?

Fair, and we did not benchmark one. Those models need you to hand them the candidate vocabulary — you have to already know the word forceps before you can find forceps. Gemma produces the word. On a tray nobody catalogued, that is the part we did not want to pre-specify. It is the first comparison I would run next.

Don't say: those need training data too. They don't, and the judge knows it.

hostileTemperature zero makes one image reproducible. Your camera never sends the same image twice. What did you actually measure?

Exactly that and no more: three runs on one image, byte identical. Stability across different frames is not measured. That is why the design asks once, when the item arrives, and never asks again — the name is fixed for the life of that item, so there is no re-query to drift. Determinism buys repeatability, not correctness.

Don't say: the model is deterministic, so naming is stable. Different claims.

hostileThe only error that matters clinically is the item that never got counted in — and your blocklist, cooldown and 8-cap can all swallow one silently. What's your miss rate?

We do not have one, and you have named the real hole. Cataloguing fails open and tracking fails safe, and the open direction is the dangerous one. What is on screen is the manifest count next to the live segmented count, so a mismatch is visible to the operator. That is a cross-check, not a measurement, and I will not call it one.

Don't say: the blocklist handles that. It's 50 hand-written words and it already let "card" through.

mediumYou claim you removed hand-built class knowledge, then hardcoded a 50-word blocklist and a rule that rewrites Gemma's answer to "fork." Isn't that a smaller labeled prior?

The fork rule is fair to hit — it patches one silhouette the model flips around on, and it should hint the display rather than overwrite the model. The blocklist I defend differently: it lists what is never an instrument — hands, sleeves, the table. Adding a new instrument still takes zero work. That is the claim, and that part survives.

Don't say: it's just a small heuristic. Own it as an override.

mediumEverything's tuned on colorful objects on a dark jacket. Real trays are specular steel on blue drape, overlapping. What breaks first?

Segmentation, before naming. The area, solidity and overlap filters were tuned on separated objects with clean edges. Steel on steel merges into one mask, and one mask means one item to everything downstream. That is a segmentation problem rather than an architecture problem, but I am not going to pretend it is small.

Don't say: Gemma has seen surgical instruments in training, so it'll be fine.

mediumYou skipped the accuracy evaluation. Design it right now.

Twenty photos of a real tray, a person writes the ground truth. Score top-1 name per instrument and report the confusion pairs, because I expect errors cluster on a few similar silhouettes. Then the number that actually matters: how many instruments placed in the zone never produced a card at all. I would rather stand here with a number from twenty photos.

Don't say: we ran out of time.

A product lead or investor

mediumIs this a medical device? What's your FDA path?

Yes, it is a device. It informs a count decision at closure, and a nurse cannot independently review why a mask stopped matching, so I do not think it clears the clinical-decision-support carve-out. Realistically a 510(k) or de novo against existing counting adjuncts, with a prospective study we do not have. Today is the technical claim, not the regulatory one.

Don't say: it's just decision support, so it's exempt.

hostileYour own writeup says accuracy is unmeasured. Would you put this in an OR tomorrow?

No. Not tomorrow and not without data. We measured latency and determinism. We did not measure whether the names are correct on a real tray. The claim I will defend is narrower: zero-shot naming removes the labeled dataset, and that part is real and reproducible.

Don't say: it worked great in our testing. There is no accuracy testing.

hostileIt false-alarms during closure. How do you avoid becoming another muted alarm?

Today it would flap — in our own event log an object that never moved flipped in and out repeatedly, because segmentation drops the mask for longer than our two-second window. That is the first thing I would fix, because a flapping alarm gets muted and a muted alarm is worse than none. The rule has to be that a flag adds a check, never delays a closure on its own.

Don't say: false positives are safe because they fail toward caution.

hostileUnbounded output is the regulatory problem, not the feature. How do you validate a model that can say anything?

Sharpest version of the question. Live today, on a dark crop, the model answered "a shirt" and "card." All that holds those out is a fifty-word blocklist, which is thin. The architecture survives it because the name is a label for a human and the alarm itself is geometry, which is bounded and testable. For a submission you freeze the vocabulary to one hospital's tray list and validate against that.

Don't say: zero-shot means it generalizes, so it'll be fine.

mediumWho signs the check? The OR director has no line item for this.

Not the OR budget — risk management. A retained item is a never-event, so the hospital eats the readmission, the second procedure and the settlement, none of it reimbursed. That is an insurance and risk line, which tolerates a per-room cost capital equipment does not. We have no pricing and no pilot, so treat it as a thesis, not a plan.

Don't say: we'd sell it to hospitals as a SaaS subscription.

A privacy and security specialist

easyWalk me through exactly what leaves this laptop during one count.

One call, to 127.0.0.1 on port 11434, where Ollama is running. That is loopback — it cannot route off the box. The page loads no fonts, no CDN scripts, no remote images, so the browser makes no outside calls either. Pull the network adapter and the count still runs. We can do that here.

Don't say: it goes over an encrypted connection, so the images are safe.

hostileDefine "on-device." I see a phone, a laptop, a network link and a separate server process.

It means no egress, not one chip. The phone captures and sends JPEGs, the laptop does every bit of inference, and the link is a USB cable with no route to the internet. Ollama is a second process on the same laptop reached over loopback. If you want the strict version, we run the identical count on the built-in webcam with the adapter disabled.

Don't say: it all runs on one device.

hostileYour README says no network calls of any kind. I can run a capture. Is that true?

As written, no. Ultralytics does a connectivity probe on import and posts its own anonymous usage events. No image, no frame, but it is a call. We set YOLO_OFFLINE=1 and measured zero calls through import, model load and predict. The sentence should say no cloud inference and no data egress. That is the claim we can defend.

Don't say: that's a library doing it, not our code.

hostileI'm on your hotspot. What stops me pulling your live frame, or posting my own frames into /ingest?

Nothing. There is no authentication on any route. Anyone on that link can pull the live frame and the thumbnails, and yes, POST /ingest would let them feed a fake instrument field into the count. The only thing protecting it today is that the link is a cable between two devices we are holding. That is a demo condition, not a control.

Don't say: nobody else would be on the network.

mediumIs it HIPAA compliant?

No, and we are not claiming it. No patient data was used at any point — household objects standing in for instruments. On-device removes the vendor and business-associate problem, which is the hardest part. Compliance also needs access control, an audit trail that survives a restart, and encryption at rest. We have none of those three.

Don't say: it's on-device, so HIPAA doesn't apply.

hostileShow me your audit trail. A patient sues in two years — what record exists?

None. The event log is a Python list in memory, capped at forty lines, and it dies with the process. That is good for privacy and bad for everything else, because in a retained-item case that record is the evidence. A real version needs a signed append-only log with a stated retention period. Right now the privacy story and the legal story point opposite ways.

Don't say: the event log on screen is the record.

Known weak spots — admit these, don't get caught on them

  • Presence tracking flaps. Seven in/out pairs in four minutes for one object that never moved, because FastSAM drops its mask past the 2.0s window. Most damaging thing that can happen on a projector. If there is time for one fix, raise HIDDEN_AFTER and loosen AREA_TOLERANCE.
  • Reset does not fully reset. The watch loop's last_count lives in another thread's stack frame. Workaround: clear the zone first, then press Reset.
  • Do not open /catalog during the demo. Manual-add entries lack the geometry keys, which raises a KeyError inside the capture loop and freezes the picture permanently. The autonomous path is unaffected.
  • The docs describe a product that no longer exists. README and CONTEXT still mention Count In / Count Out buttons and a 4-second latency. The UI has one button: Reset. Trust the code.
  • Motion trigger has almost no margin. Trigger 0.06, idle noise sampled at 0.02–0.047. The 2.5s patience timer is what saves it.
  • The blocklist barely holds. Live testing returned "a shirt" (caught, word-level) and "card" (would have gone straight onto the manifest).
  • A fresh clone cannot run. Weights are gitignored, no requirements.txt, no LICENSE despite the AGPL badge. Judges are told the repo is the source of truth.
  • Fragments are out of scope. A broken jaw tip is smaller than our minimum area and breaks off inside the wound, so it was never counted in. Real gap, not a threshold.
The closing line

What we built is a working mechanism, not a validated product. A small model running locally on a consumer laptop, with the wifi off, can name objects it was never trained on, fast enough and repeatably enough to run a count. That part is real and we measured it. A retained sponge is invisible to any camera — we watch the instrument field, not the patient. Anyone who tells you a camera solves the whole problem is selling you something.
